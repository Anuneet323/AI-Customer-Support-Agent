# Hiver AI Support Agent — Project Report

## Overview

An end-to-end AI customer support agent built on the Twitter Customer Support dataset (TWCS), brand **AmazonHelp**. The system classifies customer intent, retrieves historically similar resolved cases, generates a grounded reply, and decides whether to escalate to a human agent.

---

## System Architecture

```
Customer Message
       │
       ▼
┌─────────────────────┐
│  Intent Classifier  │  Gemini Flash (zero-shot, temp=0)
│  GeminiIntentClassifier │  → intent label + confidence
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│     Retriever       │  FAISS IndexFlatIP (cosine similarity)
│  FAISSIndex +       │  text-embedding-004 (768-dim)
│  EmbeddingModel     │  → top-k similar historical cases
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│   Evidence Gate     │  Rule-based quality validator
│   EvidenceGate      │  → passes / reason code
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│   Reply Generator   │  Gemini Flash (grounded, temp=0.3)
│   ReplyGenerator    │  → draft reply + hallucination risk
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ Escalation Policy   │  Rule-based, 7 ordered signals
│ EscalationPolicy    │  → escalate: bool + reason code
└─────────────────────┘
          │
          ▼
  PipelineOutput (JSON)
```

## Component Design Decisions

### 1. Intent Classifier (`src/intent/classifier.py`)

**Choice:** Zero-shot Gemini Flash with structured JSON output.

**Why not fine-tuned?**
- Zero-shot with a well-designed taxonomy performs surprisingly well on support messages.
- Fine-tuning requires labelled data, which this pipeline generates bootstrappingly from itself.
- Zero-shot is easier to update: change the taxonomy file, not the model.
- Gemini's JSON mode (`response_mime_type: application/json`) gives reliable structured output without post-processing hacks.

**Confidence:** Derived from the model's self-reported confidence field (0–1). Below 0.65 triggers escalation.

---

### 2. Retrieval Index (`src/retrieval/index.py`)

**Choice:** FAISS `IndexFlatIP` (exact cosine similarity) + Google `text-embedding-004`.

**Why exact search (not HNSW/IVF)?**
- Index size is ~3–5k records — well within exact search performance budget.
- Reproducibility: approximate indexes depend on hyperparameters (ef, M) and may return different results across builds.
- No tuning needed.

**What is embedded:** The first customer message of each historical conversation. This matches what's embedded at query time, maximising similarity relevance.

**Leakage prevention:** Golden set conversation IDs are loaded and explicitly excluded from the index at build time (`build_index.py` verifies this with a post-build check).

---

### 3. Evidence Gate (`src/retrieval/evidence.py`)

**Choice:** Rule-based quality gate with 4 checks:
1. At least 1 result returned
2. No near-duplicate results (similarity ≥ 0.98) — contamination guard
3. Best similarity ≥ 0.60 (configurable threshold)
4. At least 1 result with intent matching the classified intent

**Why a gate?** Without this, the generator will hallucinate plausible-sounding but wrong resolutions based on low-quality evidence. Failing the gate triggers escalation rather than a potentially harmful auto-reply.

---

### 4. Reply Generator (`src/generation/reply_generator.py`)

**Choice:** Gemini Flash at temperature=0.3 with strict grounding prompt.

**Key prompt constraints:**
- Only use facts from the customer message, context, and retrieved evidence.
- Never invent refunds, timelines, account changes, or guarantees.
- 2–4 sentences, Twitter support style (no Dear/sign-offs).
- Self-report hallucination risk and grounding used.

**Temperature 0.3:** Enough creativity for natural-sounding text, constrained enough not to fabricate facts.

---

### 5. Escalation Policy (`src/escalation/policy.py`)

**Choice:** Rule-based, explicitly ordered decision tree — **not** another LLM call.

**Why not LLM?** Escalation must be auditable. Every escalation decision has an explicit reason code and set of evaluated signals — reviewable without re-running the model.

**Escalation signals (priority order):**
1. API/generation error → always escalate (safe failure)
2. Unknown intent returned by classifier
3. Sensitive keyword detected (fraud, lawsuit, hack, chargeback, etc.)
4. Intent confidence < 0.65
5. Evidence gate failed
6. Generator flagged high hallucination risk
7. Multi-intent heuristic (≥2 question marks or "also/additionally" markers)

## Evaluation Design

### Golden Set (200 examples)

- Drawn exclusively from the **held-out split** (never seen during training or indexing).
- Intent labels: auto-generated by Gemini Flash, then reviewed.
- Escalation labels: rule-based heuristic (sensitive keywords + low confidence + low resolution confidence), then reviewed.
- Difficulty: estimated from message length, confidence, and question count.
- Leakage prevention: no golden IDs in the retrieval index.

### Metrics

| Category | Metrics |
|----------|---------|
| Intent | Accuracy, Macro-F1, Weighted-F1, Per-class P/R/F1 |
| Escalation | Precision, Recall, F1, **False Auto-Handle Rate** (most safety-critical) |
| Reply Quality | LLM Judge: 5 dimensions (correctness, groundedness, resolution, tone, non-hallucination) |
| Bootstrap | 95% CI on Macro-F1 and Escalation-F1 (n=1000) |

### LLM Judge

Gemini **Pro** (not Flash) evaluates replies on a 1–5 rubric:
- Uses a different, stronger model than the generator — reduces self-grading bias.
- Temperature = 0 for reproducible scores.
- Human-LLM agreement measured on 50 examples (Spearman r, MAD, Cohen's κ).

### Baselines

| Baseline | Description |
|----------|-------------|
| Majority | Always predicts most frequent intent, never escalates |
| TF-IDF + LR | Bag-of-words logistic regression, no retrieval |
| Proposed | Full system: Gemini + FAISS + evidence gate + escalation |

## How to Run

### Prerequisites

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Set your Gemini API key
cp .env.example .env
# Edit .env and add: GEMINI_API_KEY=your_key_here
```

### Option A: Full pipeline with real TWCS data

```bash
# Download twcs.csv from Kaggle and place at data/raw/twcs.csv

# Phase 1: Prepare data splits
python scripts/prepare_data.py --brand AmazonHelp

# Phase 2: Discover intents (optional — taxonomy already in configs/intents.yaml)
python scripts/discover_intents.py

# Phase 3: Build golden evaluation set
python scripts/build_dataset.py --n 200

# Phase 4: Build FAISS retrieval index
python scripts/build_index.py

# Phase 5: Run evaluation
python evaluation/evaluate.py --system proposed

# Phase 6: Run ablation studies
python experiments/run_experiments.py --ablation all

# Phase 7: Quick demo
python scripts/demo.py --message "My package says delivered but I never got it"
```

### Option B: Smoke test with synthetic data (no TWCS required)

```bash
# Generate synthetic conversations for all 8 intents
python scripts/generate_synthetic_data.py

# Build retrieval index (requires GEMINI_API_KEY for embeddings)
python scripts/build_index.py

# Run interactive demo
python scripts/demo.py --interactive
```

### Run Tests

```bash
python -m pytest tests/ -v
# Expected: 32/32 passing
```

## Key Design Trade-offs

| Decision | Choice | Alternative Considered | Reason |
|----------|--------|----------------------|--------|
| Intent classification | Zero-shot LLM | Fine-tuned model | Lower maintenance, no labelled training data required |
| Retrieval | FAISS exact search | Vector DB (Pinecone, Weaviate) | Reproducible, no external dependency, dataset small |
| Escalation | Rule-based | LLM-based | Auditable, deterministic, no API cost on escalation path |
| Reply grounding | Structured prompt | RAG with citation | Simpler, prompt constraints enforced at generation time |
| Evaluation | LLM judge (Pro) | BLEU/ROUGE | Captures semantic quality, not surface-level n-gram overlap |
| Confidence | Model self-report | Logprobs | Logprobs API availability varies; self-report is simpler and correlated |

## Limitations & Known Issues

1. **Single annotator** for golden set — inter-rater reliability not measured.
2. **Twitter-specific** style — system trained on short, informal messages; may degrade on formal support channels.
3. **English-only** — no multilingual support.
4. **No persistence** — pipeline is stateless; no conversation history across sessions.
5. **Rate limits** — evaluation is slow due to sequential API calls with sleep delays.
6. **Taxonomy coverage** — 8 intents may not cover rare/emerging issue types (e.g., COVID-era policies).
